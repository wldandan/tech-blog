# SPyCE：让Agent的技能和策略在训练中互相喂养

---

# 两段轨迹

同一个模型。同一道题：指针式电压表的照片拍歪了，刻度和指针挤成一团，读数区域被遮挡。Agent手里能用两把视觉工具：旋转和裁切。

第一段轨迹。Agent上来就裁了一个局部，对着歪的指针读了个数。错了。工具没用错，顺序反了：先裁切后旋转，全局方向都没摆正，读出来的数字当然不对。

第二段轨迹。Agent先扫了一眼图片整体，发现逆时针斜了，调了一手旋转摆正画面。然后定位到指针附近，精确裁切，放大确认。一气呵成，读数正确。

区别在哪？第二段Agent在推理开始前，先查了一个**技能库**。库里存着一条工作流套路："遇到旋转证据，先摆正方向再裁局部"：还挂着两条操作原语："旋转用Image.rotate"、"裁切用Image.crop"。Agent不是从零开始摸索，而是站在以前成功过的地方继续走。

SPyCE做的就是这个技能库。准确地说，**SPyCE是一个让技能库和策略在训练中一起进化的框架。**

---

# 背景：多模态Agent在"用图思考"

过去两年，多模态大模型（MLLM）的视觉推理能力涨得很快。早期路线是"文字思维链"：把图片当成一次性输入，看一眼，之后所有的推理全用文字完成。这条路在复杂视觉任务上很快碰到天花板：当你需要在高分辨率照片里找一个针尖大的目标，或者对比两张图的细微差异，或者从一张歪斜的仪表图中精确读数，纯文字推理根本够不到像素级的细节。

新范式叫**think with images**，OpenAI o3/o4、DeepEyes、OpenThinkIMG、VTool-R1等工作都在推这个方向。Agent在推理的每一步都可以主动调用视觉工具：旋转、裁切、放大、OCR、对比检查：把图片当作动态的思考草稿纸而不是静态输入快照。不再是"看图然后想"，而是"一边看一边想一边操作"。任务形态也随之变了：不再考模型能不能"看懂"一张图，而是考它能不能在多步交互中规划工具序列、利用中间结果、纠正早期误判。

但范式升级带来了一个新问题。当一个任务要横跨十几次工具调用，每一步都在改变后续的视觉证据状态，Agent就不会再碰上两张完全一样的"局面"。同一个操作模式：比如"发现图片方向不对→先旋转摆正→再裁局部"：可能分布在上百条不同任务的不同步骤里。模型如果每次都要从零开始摸索这个模式，数据效率会低得不可接受。

# 问题：RL吃掉了轨迹里的黄金

多模态工具型Agent的训练，现在主流是强化学习。给模型一个视觉推理任务，它每步从工具集中选一个动作，做完产生新的观测，循环往复，最后输出答案。答案对了，奖励1；错了，奖励0。GRPO这类方法拿这个0/1信号去调策略参数。

问题不在"用RL训练"这件事本身。问题在于：**一条成功的多步交互轨迹，里面塞满了可复用的结构化知识**：什么时候触发旋转、旋转完下一步通常做什么、裁切时怎么选区域、先旋转再裁切和先裁切再旋转的根本差在哪。这些操作模式是Agent花了几十步试错才摸索出来的。而RL只从整条轨迹里提了一个标量："对了"或"错了"。那些真正值钱的东西，被隐式地塞进模型权重里，换个新任务又得从头摸。长程任务上数据效率极低。

另一条路线是记忆增强。系统把历史交互轨迹存下来，测试时做检索，从过去经验里找参考。Reflexion、Voyager、MemP、Dynamic Cheatsheet都走这一路。但它们的策略在训练期间不更新：经验和策略各自独立运行。更强策略不会自动产出更好记忆，更好记忆也不会反过来增强策略。

两条路线各管一半。RL管了策略更新但浪费了轨迹里的结构知识；记忆管了经验留存但没跟策略形成反馈。中间缺第三个选项：**既用RL更新策略，又把轨迹里的结构化知识蒸馏成技能，让技能和策略在训练中形成相互增强的闭环。**

SPyCE（Skill-Policy Co-evolution）就是这第三个选项。

---

# 方案：三件事，一个飞轮

一句话说清SPyCE在做什么：**训练过程中，把成功的交互轨迹自动蒸馏成结构化技能存进技能库；之后的训练步里，Agent做决策前先检索相关技能作为参考；技能库跟着策略的进步持续更新。** 策略越好，轨迹质量越高，蒸馏出的技能越可靠；技能越可靠，指导出的策略越强。正向循环。

拆成三件事。

**第一件，技能从哪来。** 训练中Agent大量产生交互轨迹：每步选了哪种视觉工具、看到了什么结果。成功轨迹里藏的可复用操作模式，RL当一次性信号烧掉就没了。SPyCE换了个思路：用一个更强的多模态模型做蒸馏器，从成功轨迹里自动摘要出结构化技能条目，而不是存原始轨迹片段。存结构不存数据，检索时才能轻量、精准。

**第二件，技能怎么指导策略。** 每个训练步上Agent面对新任务，先走两级检索：从任务输入提取当前遇到什么瓶颈，去技能库里搜匹配的工作流和操作，塞进模型上下文。策略的每一步推理和工具选择不再从零开始：有一个不断进化的"前人经验库"在旁边供着。

**第三件，策略怎么反哺技能。** 每过N个训练步，从近期轨迹中筛一批高质量的，重新蒸馏技能合并进库。注意这里不是把所有成功轨迹都拿来蒸馏：SPyCE用GRPO的相对优势值做筛选，只取真正优质的那批。策略在进化、轨迹质量在上升、蒸馏出来的技能就越来越准。反复迭代。

# 两层技能：套路和动作

SPyCE把技能做了分层。一个Agent面对任务，天然要处理两类事：大方向上怎么走，这一步怎么操作。把这两类信息塞进同一个平面记忆里，检索时反而是噪音。

**下层：执行技能。** 三元组：触发条件、工具动作、预期效果。比如"证据被旋转 → 用Image.rotate → 恢复正确朝向"。粒度极细，针对单个局部视觉瓶颈，能被精确匹配、即插即用。

**上层：工作流技能。** 二元组：瓶颈描述加工作流草图。比如瓶颈是"跨区域一致性检查"，对应草图是"定位证据 → 增强局部内容 → 核对一致性"。不编码具体动作，只告诉Agent这类情况大思路应该怎么走。

技能的来源是轨迹，但蒸馏过程完全不存原始轨迹：每次都用MLLM重新摘要成结构化条目。检索时直接按语义匹配，不用把几千Token的轨迹上下文怼进推理窗口。

技能多了会自动治理。每条新候选进库前，先在嵌入空间里跟已有技能比对：触发条件相似的执行技能合并、瓶颈描述相似的工作流技能合并。够不着相似度阈值才新增。容量超了，淘汰命中率最低的条目。技能库不会无限膨胀。

# 飞轮怎么转

每个训练步，正向和反向同时跑。

**正向：技能→策略。** Agent收到任务，先从输入提取瓶颈描述（"这图里什么绊住了我？"），去工作流技能库搜Top-K匹配。拿到工作流指引后，把任务进一步拆成细粒度局部瓶颈："方向需要摆正""指针区域太挤需要放大"：逐个去执行技能库匹配最佳操作。两级检索的结果一起塞进上下文，策略的每一步都站在前人经验上走。

**反向：策略→技能。** 每N步开进化窗口。用GRPO的相对优势值从近期轨迹中筛Top-ρ条高质量样本，重新蒸馏技能，合并或新增入技能库。策略越训越强，产出的轨迹越来越靠谱，蒸馏出来的技能自然越来越精准。回合往复。

论文的图上画得很清楚。训练早期，执行技能的数量和平均成功率同步爬升：新技能不断被发现，旧技能通过合并机制持续提纯。中后期库接近容量上限，数量不再涨，进化主要在条目质量层面发生：同样的操作，描述越来越准、边界条件越来越清晰。工作流技能的数量始终稳定在较小区间：套路不需要多，管用的几条就够。有意思的是，执行技能的平均成功率在训练全程都在涨：策略越训越强，产出的轨迹里藏着更深层的规律，蒸馏也不断从中挖掘出更好的技能。

冻住技能库做消融：准确率直接掉3.1个百分点，工具调用次数从4.83涨到5.54。不转的飞轮，技能退化成一本落灰的参考手册。

# 数字

八个基准测试，三层任务：TIR-Bench（工具型视觉推理）、MathVerse/MathVision/WeMath/ChartQAPro（多模态推理）、V*/HRBench（视觉搜索）。Qwen3-VL-4B和8B两个骨架模型。GRPO做纯RL基线，MemP/Dynamic Cheatsheet/Agent-KB做记忆基线。SPyCE在每个基准、每个模型规格上全部跑赢。

TIR-Bench上Overall准确率32.0%，GRPO是27.7%，高出4.3个百分点。同时工具调用更少：4.83次对5.13次。用更少的步骤拿到更高的成功率：技能引导让Agent的每一步都更有目的。

消融拆开：去掉工作流技能 -4.0%；去掉执行技能 -3.3%；冻住技能不进化 -3.1%；去掉工具调用效率惩罚 -2.6%且工具调用飙到6.83。两层互补，闭环必需，效率约束不能省。

收敛速度也好看。训练刚开始SPyCE就明显拉开GRPO：技能库给了初始探索一个方向，不是白纸上画线。

# 跟Skill治理的接口

SPyCE和Agent-insight的Skill生命周期治理，底层逻辑一致：**Skill不应该是一锤子写死的配置文件。它可以从Agent的真实交互中持续生长。**

Agent-insight用四维评测门禁决定Skill能不能上线，用版本管理保证出问题能回滚。SPyCE补上了"Skill从哪来"这块：不是人写的，是训练中自己长出来的。两套机制接起来：训练阶段用SPyCE自动生成和进化Skill，上线前用四维评测验收，上线后用Agent-insight持续观测和治理：Skill就从别人的手工艺品变成了自己的、活的、能持续进化的资产。
