# UCOB：让 AI Agent 学会"有选择地相信"技能记忆

## 引言：当技能记忆成为双刃剑

想象这样一个场景：你正在训练一个 AI Agent 在模拟环境中完成任务——比如在厨房里找到苹果并加热。Agent 在几十次尝试后，终于摸索出了一个有效的策略："先去查看餐桌，如果找不到就去翻冰箱。"它把这条经验存入了技能记忆库。当它下次面对类似任务时，系统检索出这条技能提示，注入到上下文中，期待它能引导 Agent 做出更好的决策。

但问题来了：这条经验真的总是有用吗？

如果这次苹果在微波炉里，而那条"先去餐桌"的技能不仅帮不上忙，反而会误导 Agent 浪费宝贵的步数。这就是当前技能增强型 Agent 训练面临的核心困境——**检索到的技能并非神谕，它们在某个状态下可能是锦囊妙计，在另一个状态下却可能是指挥棒乱挥**。

来自中科院自动化所、鹏城实验室和 MemoraxAI 的研究团队在最新的论文中直面了这个问题，提出了 **UCOB**（Credit-aware On-policy Bidirectional self-distillation），一个让 Agent 学会"有选择地相信"技能记忆的统一框架。

---

## 核心问题：技能上下文凭什么当老师？

在当前的 Agentic RL（智能体强化学习）范式中，一个常见的做法是：将检索到的文本技能注入 prompt，形成"技能条件化"的上下文，然后将其视为"特权教师"（privileged teacher），用它的输出分布去监督没有技能的"学生"模型。像 SDAR、Skill-SD 等方法都遵循这样的设计逻辑。

但研究团队在论文的第 2 章给出了一个令人警醒的诊断：

**1. 技能条件化的教师并不总是比无技能视图更强。**

在 ALFWorld 和 WebShop 两个环境中，带有技能上下文的评估得分并没有一致地领先于不带技能的评估。在 WebShop 上，带技能的评估得分甚至在训练全程都低于不带技能的表现。这意味着，给模型加上技能上下文，并不会自动产生一个可靠的教师信号。

**2. 即使让技能视图也在环境中在线交互（on-policy），歧义依然存在。**

一个自然的补救措施是让技能视图也参与到实际的环境交互中，而不是仅仅在"教师"的位置上旁观。但实验表明，即使采用了双轨 rollout（一半轨迹带技能、一半不带），技能轨迹的平均奖励有时依然低于无技能轨迹。

**3. 同一轨迹的不同步骤，哪个视图更好是动态变化的。**

研究者按照"锚定状态"（anchor state）对 rollout 记录进行了分组，比较了同一状态下技能视图和无技能视图的回报差距。结果发现：差距是有正有负的——在某些状态组中技能更好，在另一些中无技能更好。甚至在同一条轨迹的不同决策步骤上，哪个视图更优也会动态切换。

这一系列观察指向同一个结论：**教师方向不应该由"有没有技能"来决定，而应该由每个局部状态下的实际回报来决定。**

## UCOB 的核心思路：让回报说话

UCOB 的设计哲学可以用一句话概括：

> 不要假设技能总是好的。在同一任务、同一状态下，让实际的环境回报来决定谁来当老师。

具体来说，UCOB 将技能条件化 prompt 和无技能 prompt 视为**同一个模型的两种 on-policy 上下文视图**，而不是预先固定的师生关系。训练时，它在同一任务和锚定状态内比较两个视图的 return-to-go（未来累积回报），然后将**高回报视图**选为局部教师，向相反上下文进行蒸馏。这个机制被称为 **CBSD（Credit-Aware Bidirectional Self-Distillation）**。

**双向意味着什么？**

- **当技能确实有帮助时**（技能视图的回报更高）→ 将技能条件化行为蒸馏到无技能视图，让模型内化有用的策略。
- **当技能产生误导时**（无技能视图的回报更高）→ 无技能视图反向纠正技能条件化行为，拒绝不可靠的技能提示。

这种设计将"技能利用"和"技能纠错"统一在了同一个信用分配框架下，实现了策略学习和技能演化的闭环。

## 架构解析：四个关键模块

UCOB 的完整流程包含四个紧密耦合的模块：

### 1. 双层技能记忆与混合 Rollout

UCOB 维护两个层级的技能池：

- **任务级技能（Task-level skills）**：捕获跨回合的可复用策略，比如"在 WebShop 中，先检查产品规格再比较价格"。
- **状态级技能（State-level skills）**：捕获局部决策规则，基于同状态下的回报对比生成，比如"当搜索框可见且历史为空时，直接输入精确查询词"。

技能检索采用基于 UCB（Upper Confidence Bound）的评分机制，平衡了语义相似度和历史效用。每个技能维护一个动态更新的效用分数，帮助系统在探索新技能和利用已知好技能之间取得平衡。

训练时，每个任务组采样一半带技能、一半不带技能的 rollout，两种视图都与环境在线交互，为后续的信用比较提供配对的 on-policy 证据。

### 2. 信用感知双向自蒸馏（CBSD）

这是 UCOB 的核心创新。对于同一个锚定状态下的所有 rollout 记录，CBSD 首先选出 return-to-go 最高的记录作为**信用参考**（credited reference），然后将它的响应分布蒸馏到相反上下文的视图上。

关键细节包括：

- **回合差距门控（gap-gated）**：只有当回报差距超过阈值时，才激活蒸馏信号，避免在差距很小的时候引入噪声。
- **Top-K 令牌支持匹配**：借鉴了 teacher top-K 局部支撑匹配的思想，让目标视图只在参考视图的 Top-K 高概率令牌集合上学习，提供更稳定的监督信号。
- **置信度门控（confidence gate）**：在令牌级别通过 sigmoid 门控抑制参考视图不够自信的位置。

理论分析（附录 C）进一步给出了一个局部策略改进的解释：当分支排序正确且更新幅度较小时，CBSD 的蒸馏方向保证了对局部优势代理的正向贡献。

### 3. 技能记忆演化

UCOB 不仅使用技能，还持续演化技能。利用 CBSD 中产生的信用证据：

- **任务级技能**：通过反思整个 rollout 组来生成和更新。
- **状态级技能**：通过对比同锚定状态下高回报和低回报记录来生成，天然地基于局部价值对比而非轨迹级总结。

每个技能的效用分数通过 EMA 在线更新，高分技能在后续检索中更容易被选中，形成正向反馈循环。

### 4. 技能写作器自训练

UCOB 还进一步训练负责写技能的"反思写作器"。它利用技能效用计算池归一化的反思优势（reflection advantage），通过裁剪策略梯度损失来调整生成技能文本的概率。高实用性的记忆获得更高的生成似然，低实用性的记忆被抑制。

最终，UCOB 的联合损失函数将在线 RL 损失、CBSD 损失、反思损失和 KL 正则化项统一在一起。

## 实验：用数据说话

研究团队在三个主流的 Agent 基准上进行了全面评估：

| 方法 | ALFWorld (Qwen3-1.7B) | WebShop (Qwen3-1.7B) | ALFWorld (Qwen2.5-7B) | WebShop (Qwen2.5-7B) |
|------|----------------------|---------------------|----------------------|---------------------|
| Skill1 | 65.6 | 61.7 | 92.2 | 77.3 |
| SDAR | 53.9 | 58.6 | 85.9 | 82.8 |
| **UCOB** | **89.1** | **79.7** | **93.0** | **85.9** |

在一个紧凑的 Qwen3-1.7B 模型上，UCOB 在 ALFWorld 和 WebShop 上分别超出 SOTA 方法 **+23.5** 和 **+18.0** 个百分点。在更大规模的 Qwen2.5-7B 和 Qwen2.5-3B 上，UCOB 同样保持了稳定的领先优势。

在 SEARCH-QA 上，UCOB 也保持有竞争力的表现，证明了该方法不仅适用于多轮交互环境，也能保留强大的搜索式问答能力。

### 消融实验的关键发现

消融实验揭示了一个重要结论：**同时移除混合 rollout 或 CBSD 带来的性能退化，远大于单独移除双层记忆或反思训练。** 这意味着，将技能直接混入 on-policy rollout 并不是信用分配问题的替代方案——显式的局部蒸馏信号才是关键。

CBSD 内部的消融进一步显示：
- 仅保留回合差距门控但限制为技能→无技能单向蒸馏 → 不如完整的双向蒸馏
- 固定方向的蒸馏 → 在技能局部较差时会带来损害
- 移除 Top-K 支持匹配 → 监督信号稳定性下降

## 深度分析：技能记忆真的有用吗？

论文的分析部分提供了几个值得深思的发现：

**1. 技能的可靠性被高估了。** CBSD 在训练过程中的路由统计显示，无技能→技能的蒸馏方向出现的频率高于技能→无技能的方向。这说明在很多局部比较中，不带技能的纯模型尝试反而给出了更强的决策——技能并不像我们想象的那么可靠。

**2. 双向蒸馏让两个视图协同进化。** 在固定方向的双轨 SDAR 中，技能视图和无技能视图的表现差距始终存在。但在 UCOB 中，两个视图的表现差距持续缩小，无论评估时是否提供技能，模型都保持有效。这意味着有用的技能行为被有效地内化到了模型中。

**3. 记忆在增长，但质量在保持。** 随着训练推进，技能库持续扩张，但检索到的技能的平均效用分数始终保持为正，有效技能的比例也没有衰减。反射写作器的训练信号保持活跃，表明技能演化是一个健康的自我迭代过程。

**4. 外部强写手不能替代自我演化。** 使用外部 GPT-5.4 写技能的效果不如 UCOB 的自我训练反思——这说明框架的增益并非来自于更强的外部生成器，而是来自于信用感知的在线演化机制。

## 总结：Agent 训练的"信用观"

UCOB 的工作值得关注的不仅是它在多个 benchmark 上的 SOTA 成绩，更是它对技能增强 Agent 训练范式的重新审视。核心洞察可以被提炼为三个层次：

**第一层：技能≠权威。** 检索到的文本经验是候选建议而非金科玉律。同一个技能在状态 A 可能是妙招，在状态 B 可能是毒药。

**第二层：回报是最好的裁判。** 与其预设固定的师生方向，不如让同一状态下的实际环境反馈来裁决。这是信用分配（credit assignment）思想从 RL 动作级向上下文级的自然延伸。

**第三层：利用和演化要闭环。** 技能不应该是一次性写入的静态资产。在利用技能辅助决策的同时，持续用新的交互经验更新技能质量和检索机制，才能让记忆库保持生命力。

对于正在从事 Agent 训练、RL for LLM 或技能记忆相关工作的研究者来说，UCOB 提供的"信用感知双向自蒸馏+技能演化"框架值得深入研究和借鉴。
