# 开源社区有82万个技能文件，扔进Agent有用吗？

---

# 一个没人回答的问题

Agent技能生态在过去一年里炸了。Anthropic推了SKILL.md规范，OpenAI推了Agent SDK，社区跟着涌进来，GitHub上几万个仓库在发布技能文件。到SkillCorpus做这次研究的时候，公开渠道上能爬到的原始SKILL.md文件已经超过**82万个**。

但一个尴尬的事实一直没人正面回答：**把这些社区技能喂给Agent，到底能不能让它变强？**

之前的研究给出了两种相反的信号。精心挑选的技能一对一配给任务，确实能提分。但不加筛选的社区技能库直接往Agent里灌，不光不提分，有时候还倒退。问题出在"不加筛选"——82万个文件中大量是重复的、低质量的、许可证混乱的，没人系统地做过聚合、去重、质量把关和评测。

SkillCorpus团队做了一件事：把整个开放的SKILL.md生态吞进去，嚼碎，吐出一个干净、可用的技能语料库，然后在真实Agent任务上测了一圈，告诉大家这个库什么时候管用，什么时候不管用。

---

# 从82万到9.6万：六道工序

入口是62个源头的聚合，覆盖GitHub仓库、Awesome清单、市场API、站点爬虫和JSON目录。原始爬取拿到约82.1万个SKILL.md文件，去掉仓库级重复后，25,159个仓库进管道。

第一条管道是去重，也是砍得最狠的一道。先做精确去重——按内容指纹和名称指纹比对，169,465个文件发现是完全相同的副本，直接砍掉，占输入量的59.7%。这个数字本身就是一个发现：**开源技能生态里将近六成是同一个东西在各个仓库之间复制粘贴。** 然后是语义去重：嵌入相似度超过0.90的标记为近似重复，让LLM裁判来判断是否合并。0.995以上直接自动合并，0.90到0.995之间的66,751对由裁判裁定。最终确认了25.4%的确为重复，合并掉13,268个近乎相同的技能。去重这一道总共干掉了64%，从28.3万砍到10.1万。

第二条管道是质量评分。SkillCorpus把技能质量拆成三个独立的维度。**实用性**只看描述，任务范围是否清晰、触发条件是否明确。**鲁棒性**看正文内容跟描述的承诺是否一致：描述说能干的活，正文里的流程是否真的覆盖了。**安全性**是独立的一轴，检查Prompt注入、命令注入、凭证泄露、越权执行等11类风险。三个维度的得分做了有意为之的分离，实用性和鲁棒性之间的相关性不低（r=0.59），因为两者都关乎工件的做工质量；但安全性跟这两者的相关性很低（r=0.15和0.30），因为一个写得好的技能同样可以不安全。

第三条管道是硬闸门。五类安全Flag一旦触发，直接归零排除：Prompt注入、命令注入、不安全执行、认证绕过、CSAM风险。再加一道OSI许可过滤器，只留下许可证开放的技能，砍掉3,795个。最终放行的**96,401个技能**，任何人在任何项目里都可以商用分发。

第四条管道是分类。16个类别，从Dev（22.4%）、Data（14.1%）、Writing（8.2%）到Security（4.1%）、Auth（1.7%）。软件和数据类占了半壁江山。分类不是装饰，后面的检索策略会根据Benchmark自适应调整类分布权重。

# 检索栈：召回、重排、精读

语料库打包好不等于Agent会用。SkillCorpus配了一套检索选择栈：召回→重排→LLM精读。

**召回和重排**用的是两阶段微调模型，都基于Qwen3，在严格去重后的活跃技能集上做对比微调。去重不单是为了语料库干净——低重叠的数据分布给对比学习带来了更干净的信号，功能完全一样的近似副本不会在训练中互相充当难负样本。

**LLM精读层**是这一步的关键。重排后的Top-K候选仍可能混进话题相关但实际不匹配的技能，简短的摘要信息不够让Agent在运行时精确判断。SkillCorpus在重排之后再加一个LLM选择器：把每个候选技能的完整正文和任务查询一起喂进去，返回0到2个精确匹配的工具。多花一次LLM调用，换来完整正文检查带来的匹配可靠性，同时把注入上下文的Token量控制在每任务的严格预算内。

一个可选组件是查询改写器：当任务的领域术语跟技能库里的描述词汇对不上时，LLM把任务改写成语料库更"听得懂"的表达。任务明显超出语料库覆盖范围时，改写器可以直接短路，不推技能，避免强行匹配制造噪音。

# 在三张考卷上答题

评测设计得很扎实：三个Benchmark（SkillsBench的87个确定性验证任务、GDPVal的220个真实经济任务、QwenClawBench的100个真实用户分布任务），两种独立的Agent Harness（OpenClaw和Raven），两个骨架（Qwen3.5-27B和397B），加一个前沿模型鲁棒性检查（Claude Opus 4.7）。总共407个任务，26个领域，74次端到端运行。

**所有三个Benchmark上，加SkillCorpus都比不加强。** SkillsBench上提升最明显，跨四个开放骨架配置平均+7.5个百分点（p<0.001），最强的Raven×Q-397B配置+13.4pp。在其中一个运行中，这个配置救回了19个基线失败的任务，同时只打破了2个。Claude Opus 4.7的前沿检查+8.0pp——**即使强如Opus，外部技能库仍然有明显增益，不是模型强了就不需要技能了。** Opus的无技能基线是39.1%，加上SkillCorpus到了47.1%，增益幅度跟开放模型跨配置均值属于同一量级。

GDPVal和QwenClawBench的任务基准线本来就高（65-85%），天花板效应限制了增益空间，但跨四个配置的池化增益仍然统计显著。

**消融实验讲了两个故事。** 把精调检索栈换成Qwen3的现成嵌入和重排序模型，SkillsBench正确率从22.6%掉到13.8%。把过滤后的语料库换成82万原始爬取文件，掉到14.9%。两者都在无技能基线（9.2%）之上，但远低于完整管道。语料库质量和检索精度各贡献一块，缺一不可。

**语料库覆盖度决定了增益的天花板。** 把任务按最佳匹配技能的检索得分分三组：低覆盖组平均+2.2pp，高覆盖组平均+25.1pp。覆盖不到的地方，增益不是负的，它归零，因为检索器推不出来就不推。拉高覆盖是供给端的问题，不是检索算法的问题。

---

# Harness决定你能兑现多少增益

一个容易被忽略的发现。两种Harness收到完全相同的技能选择，也都正确读取了注入内容。区别在**技能注入之后发生了什么**。

Raven有一个执行-验证-修复循环，技能内容通过这个循环转化为验证通过。OpenClaw在推理阶段写完脚本后经常停下来不执行，不跑验证器。所以同样的技能内容，在Raven上兑现了+13.4pp，在OpenClaw上只兑现了+5.8pp（同是Q-397B骨架）。技能的实际效用是**语料库和Harness的联合属性**，不是语料库自己的事。这个发现也解释了为什么更简单的GDPVal任务上两个Harness差距消失，GDPVal的打分靠LLM裁判评输出质量，不靠验证器循环。

# 一个可用的结论

SkillCorpus给出了第一份端到端的证据：**一个经过系统去重、质量评分、安全筛选的社区技能语料库，配上一套精调的检索选择栈，在多种真实Agent任务上都能稳定提分。** 提多少取决于两个边界：语料库有没有覆盖到这个领域（覆盖度边界），Harness能不能把技能内容充分转化为任务结果（Harness边界）。

对Agent平台来说，这个结论意味着：社区技能不是鸡肋，但你不能直接拿来用。聚合、去重（占管道削减量的64%）、质量评分、安全闸门、许可证审查——这些不是锦上添花，是决定"有用还是倒退"的前提条件。聚合本身就是一个大工程：62个源头、五种抓取机制，从GitHub仓库到市场API到站点爬虫。而且质量评分值得单独拎出来说——SkillCorpus的三维评分框架（实用性、鲁棒性、安全性）提供了一个可操作的分拆思路，团队可以根据自己的容忍度对每维设不同的准入阈值，而不是用一个模糊的"质量分"糊在一起。

对Skill生命周期治理来说，SkillCorpus补上的是"入口治理"这一环。Agent-insight做的是单个Skill的质量评测和持续进化，SkillCorpus做的是大规模技能库的聚合和准入治理。两条线一横一纵：SkillCorpus决定哪些技能能进库，Agent-insight决定进库的技能怎么持续好下去。
