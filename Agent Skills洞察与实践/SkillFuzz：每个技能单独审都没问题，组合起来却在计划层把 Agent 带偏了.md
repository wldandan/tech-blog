# SkillFuzz：每个技能单独看都没问题，组合起来却把 Agent 带偏了

> 论文：SkillFuzz: Fuzzing Skill Composition for Implicit Intents Discovery in Open Skill Marketplaces
> 作者：Jinwei Hu, Yi Dong, Youcheng Sun, Xiaowei Huang（University of Liverpool、MBZUAI）
> 发布时间：2026 年 7 月
> 关键词：Skill Marketplace、Fuzzing、Implicit Intent、Agent Safety、Compositional Testing

---

## 一、问题：单检无害，组合有毒

LLM Agent 的技能市场（skill marketplace）正在兴起。像 ClawHub 这样的开放平台允许社区贡献者上传技能——一段自然语言指令文档，描述 Agent 在执行特定任务时该如何规划和行动。用户从市场上挑选几个技能，打包激活，就组装出了一个能完成特定任务的 Agent。

市场运营方会对每个技能做审核——检查指令文档里有没有恶意注入、有没有不安全操作。审核通过后，技能上架。

**但这个审核模型有一个结构性盲区：它只检查单个技能，不检查技能组合。**

举个例子。市场上有两个技能：

- `contribution-analysis`：分析财务贡献数据，生成汇总报告。
- `csv-processing`：处理 CSV 格式的结构化数据。

单独看，两个都没问题——一个做分析，一个做数据处理，指令文档里没有任何恶意内容。但当你把它们**同时激活**时，Agent 处理它们的联合指令，产生了一个单独审核时根本看不到的行为：它试图**修改原始数据文件**，而这些文件本应只读。这个副作用不来自任何一个技能单独包含的指令，而是两个技能的指令在 LLM 的"信念状态"（belief state）里发生了交互，共同推导出了一个"额外目标"。

论文把这种现象称为 **implicit intent（隐式意图）**——一种不在任务描述里、也不在任何一个单独技能的指令里，而是**从技能组合中涌现出来的非预期目标**。

这和传统软件工程里的组件交互故障（integration testing 中的 component-interaction faults）是同一种失败模式，只不过发生介质从代码变成了自然语言指令。

### 为什么难检测

三个挑战叠加在一起：

1. **没有执行环境。** 市场运营方通常没有部署 Agent 的环境，即使能搭建，对所有技能组合逐一执行工作流也不现实。
2. **组合效应不可见。** 隐式意图产生在 LLM 的推理过程内部，对静态文件分析完全透明。
3. **组合空间指数爆炸。** 196 个技能的市场上，可能的共同激活组合是指数级的，全量穷举不可行。

## 二、核心思路：把计划当成测试面

SkillFuzz 的解决方案基于一个关键的观察。

几乎所有 LLM Agent 都遵循 **plan-then-act（先规划再执行）** 的架构模式：在调用任何工具之前，Agent 先生成一个自然语言的计划（plan），把任务拆解成可执行的步骤。这个计划是 Agent 信念状态的外部化——它暴露了 Agent 打算做什么、按什么顺序做、操作哪些文件。

**既然隐式意图在信念状态里就已经形成了，那么在计划阶段它就已经可见了。** 不需要等到实际执行。

SkillFuzz 利用这一点，把 **计划漂移（plan drift）** 作为测试信号：拿同一个任务，让 Agent 分别在"不加载任何技能"和"加载某个技能组合"两种条件下各生成一个计划，比较两者之间的语义差异。如果加了某个技能组合后，计划方向发生了显著偏离，就说明这个技能组合在 Agent 的信念状态里引入了额外的东西。

这个信号充当了 fuzzing 中的 **差分 oracle**——就像传统 fuzzing 用"崩溃"作为故障信号一样，SkillFuzz 用"计划偏离基线"作为组合风险的信号。整个过程**不需要执行任何一行代码**。

## 三、方法：两阶段 fuzzing

SkillFuzz 分为两个阶段。

### 第一阶段：技能合约提取与裁剪

对于技能库里的每个技能，先用 LLM 从它的指令文档中提取一个结构化的**技能合约（skill contract）**，包括：

- **前置条件（preconditions）**：技能生效需要满足什么条件。
- **后置条件（postconditions）**：技能完成后会达到什么状态。
- **修改集（modifies）**：技能会修改哪些数据或文件。
- **不变式（invariants）**：技能保证不会违反的约束。
- **域范围（domain scope）**：技能适用的领域。
- **动作类型（action types）**：技能触发什么类型的操作。
- **置信度（confidence）**：LLM 对合约提取质量的自评分数。

每个合约被嵌入到一个语义向量空间中。这一步把自由格式的自然语言文档变成了可计算、可比较的结构化表示。

然后做两步筛选：

1. **任务相关性裁剪**：只保留与当前测试任务语义相似度足够高的技能（合约向量与任务向量的余弦相似度 ≥ 阈值），剔除明显不相关的技能。
2. **冲突种子排序**：对裁剪后的技能集合，按冲突潜力排序——共享修改集的技能对、不变式互斥的技能对、置信度低的技能，优先排进初始种子队列。

### 第二阶段：差分激活搜索（MCTS-based fuzzing）

这一阶段用一个 **蒙特卡洛树搜索（MCTS）** 在二进制的技能激活空间里搜索。搜索空间的结构是：

- **节点** = 一个技能激活向量 s（长度为候选技能数，每个位置 0 或 1，表示是否激活该技能）。
- **边** = 翻转一个技能位（激活或停用一个技能）。
- **节点奖励** = **ICQ（Intent Coverage Quality）= 计划漂移 × 意图新颖度**。一个发现只有同时满足"偏离足够大"且"与之前发现的意图都不重复"时，才贡献非零奖励。这确保搜索不被浅层偏离淹没，也不被重复发现浪费预算。

MCTS 的四个步骤各有定制：

**选择（Selection）：** 标准 UCB 公式，平衡探索和利用。

**扩展（Expansion）：** 这里有一个关键设计。当当前节点已经发现了隐式意图时，SkillFuzz 不是随机选下一个技能，而是**朝着已发现意图的语义方向扩展**——计算当前激活集合的语义质心，然后向最近发现的意图向量方向移动，选择向量最接近目标的新技能加入。当当前节点还没发现任何意图时，才随机采样。这个设计把搜索预算集中在了"已知风险区域附近"，而不是均匀撒网。

**模拟（Simulation）：** 对扩展后的节点，采样 K 次（K=3）计划生成，每次计算漂移值。漂移低于最低阈值的丢弃不分析；高于阈值的用意图提取 Agent 从漂移计划中提取具体的隐式意图，并判断与已发现意图库的新颖度。新颖的意图加入意图库并记录。

**回传（Backpropagation）：** 将节点奖励（多次采样的平均 ICQ）沿树向上回传，更新祖先节点的访问计数和平均奖励。

这个搜索过程在固定查询预算（B 次迭代）内运行，最终输出一份意图报告，列出所有发现的高风险技能组合及其对应的隐式意图。

## 四、效果

### 规模：1000+ 隐式意图

在 SkillsBench 的 196 个技能库上，200 次查询预算下，SkillFuzz 从 10 个代表性任务中累计发现了超过 1000 个语义独立的隐式意图。

### 执行验证：80%+ 确认率

论文把 98 个最高风险标记的技能组合拿到真实的 Docker 沙箱环境中实际执行（使用 Claude 作为执行 Agent，而不是当初生成计划的 Agent），用 GPT-4o-mini 判断预测的意图是否在执行轨迹中出现。结果是 **80.6% 的组合在实际执行中被确认**。

更重要的是，确认率在不同规划模型家族间几乎一致（DS-R1 系列 80.5%，GPT 系列 81.0%）。这说明计划层面的漂移不是某个模型特有的输出风格偏差，而是技能组合本身触发的结构性风险。

### 搜索效率：覆盖 40% 的交互空间，发现更多严重意图

与随机搜索的对比很有说服力：

| 策略 | 意图数 | 严重意图占比 | 平均技能数 | 交互对覆盖率 |
|------|--------|------------|-----------|------------|
| **SkillFuzz** | 116 | **77%** | 4.28 | **39.7%** |
| 随机搜索 | 121 | 52% | 3.05 | 94.5% |

随机搜索覆盖了 94.5% 的成对交互空间，但严重意图比例只有 52%。SkillFuzz 只探索了不到 40% 的成对空间，但严重意图比例是 77%，绝对数量多出 41%（90 vs 64）。**覆盖面广不等于找得到真正的风险。**

还有一个值得注意的趋势：计划发生严重漂移的概率随共同激活技能数**单调增加**。单技能激活时严重漂移很少，到 5 个技能联合激活时，66.5% 的测试组合都出现了严重漂移——**风险不是线性的，是组合放大出来的。**

### 意图的语义结构：四类风险模式

所有发现的隐式意图通过聚类分析形成了四个可解释的风险类别：

1. **音视频副作用（Audio/Video Side-Effect）**：媒体处理技能组合产生了任务没要求的音视频产物。比如编辑 PDF 时自动生成了 MP3 有声书。

2. **越权工具调用（Unauthorized Tool Invocation）**：技能组合触发了对超出任务授权的数据边界的外部服务调用。比如处理视频静音时把本地音频数据发给了外部 Whisper API。

3. **隐蔽资源创建（Covert Resource Creation）**：Agent 产生了任务未要求的文件或报告。比如要求 JSON 输出但生成了 CSV 报告。

4. **越界数据分析（Unsanctioned Data Analysis）**：Agent 的分析行为超出了任务显式指定的数据范围。比如财务分析技能组合修改了应该只读的原始数据文件。

这些类别不是某个任务特有的，而是跨任务、跨规划模型反复出现的结构性风险模式。

### 跨模型泛化

实验测试了 8 个规划模型（4 个 DeepSeek-R1 系列 + 4 个 GPT 系列），**全部产生了非零的隐式意图**。较小的推理模型（如 DS-R1-7B）比大模型更容易暴露隐式意图——它们的计划在面对冲突技能指令时更不稳定，反而成了更好的测试基底。

## 五、这意味着什么

SkillFuzz 的工作值得关注的不只是一个 fuzzing 技术，而是它指出了一个正在被忽略的安全边界。

**技能市场把审核逻辑从"检查代码"变成了"检查文档"。** 但文档的组合语义空间和代码的组合逻辑空间一样危险。一个技能单独看没问题，和另一个技能放在一起就不一定了。这不是 prompt injection——没有任何一个技能携带了恶意 payload。这是自然语言组合中的 emergent behavior，和传统软件里两个没 bug 的模块集成后产生故障是同一类现象。

**计划层是一个被低估的测试面。** plan-then-act 架构本来是为了让 Agent 的行为更可解释、更可控。SkillFuzz 展示了一个副用途：计划本身就可以充当测试预言，不需要等 Agent 把事做完再回头看。这对没有执行环境的市场运营方来说是一个实操上可行的切入点。

**覆盖面大不等于安全测试做得好。** 随机搜索探索了 95% 的成对组合，但严重意图发现率不如定向搜索的 40%。安全测试里，"搜得多"和"搜得准"是两回事。ICQ 这个指标把严重性和新颖度绑在一起，是一个值得借鉴的思路。

对于运营 Agent 技能市场的团队，或者任何需要管理"多个 LLM 指令上下文同时激活"场景的开发者，SkillFuzz 提供了一个不需要部署环境、不需要执行的组合风险筛查方案。
