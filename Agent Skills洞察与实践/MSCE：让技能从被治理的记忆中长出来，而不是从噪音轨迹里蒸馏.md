# 你的Agent攒了一堆经验，但每次还是从头开始推理：问题出在"记忆"和"技能"之间的那道墙

---

# 记忆是死的，技能才是活的

Agent跑了一个长任务。它反复进出同一个代码仓库，每次都要重新list目录找测试文件在哪、配置文件在哪、构建脚本在哪。这些操作在Agent的记忆里已经存了好几次，每次都是差不多的轨迹，差不多的步骤。但记忆只是把过去的交互记录扔进上下文窗口，Agent还是得重新推理一遍。

这不是模型不够聪明。是**记忆和技能之间少了一个转换机制**。

记忆存的是"发生过什么"。技能存的是"应该怎么做"。把轨迹变成可执行的技能，这件事比想象中要难得多。原始轨迹里掺杂了大量失败的尝试、盲目的探索、环境相关的噪音。终局反馈往往稀疏且延迟，一个任务跑了二十步最后得了个0/1奖励，你根本不知道哪一步是关键贡献、哪一步纯属走弯路。直接拿这些噪音轨迹去蒸馏技能，得到的是一堆在错误场景下被错误触发的脆弱指令。

一篇来自MemTensor和港理工等机构的新论文提出了MSCE，全称Memory-Skill Co-Evolution。核心理念就一句：**技能不应该从原始轨迹直接蒸馏，而应该从被治理的记忆中逐步生长出来。** 训练无关，不更新模型权重，只治理外部的记忆结构和技能库。

---

# 三层记忆：证据、策略、认知

MSCE把Agent的记忆分了三层。不是三份数据，是**三种不同的抽象等级**，各自解决各自的问题。

**L1：轨迹记忆。** 存的是最底层的交互证据。每一步的状态、动作、观测、自我反思，都被结构化保存下来。关键设计：L1不存无界的原始观测，截断状态文本、只保留工具调用的结构化元数据、限制工具输入输出长度。更高层的记忆只存证据标识符，不复制原始数据。这么做有两个目的：控制存储膨胀，削减隐私风险。

**L2：策略记忆。** 从L1的轨迹证据中归纳出可复用的过程性模式。每个L2策略是一组字段：触发条件（什么情况下适用）、自然语言描述的可执行流程、验证或回退准则、适用范围边界、以及支撑它的L1证据集合。策略不是一次性生成就定型，新的高质量轨迹到来时，MSCE会按嵌入相似度加结构化证据（领域标签、工具类型、错误签名）把轨迹匹配到已有策略上，更新或新增。同一个模式签名下攒够至少n条来自不同episode的证据，才触发策略抽取。这是有意设的门槛：不靠单条偶然成功的轨迹就拍脑袋总结规律。

**L3：环境认知。** 比策略再高一层。策略说的是"怎么做一件事"，环境认知说的是"这个环境本身是怎么组织的"。多个活跃L2策略共享同一个领域或环境上下文时，MSCE把它们抽象成L3，实体结构、操作规律、环境约束。比如反复出现的"编辑前端文件→定位测试→修改配置"这一组策略，支撑起一个"仓库环境认知"。L3只萃取声明式事实，不含可执行操作指令。后续技能在被调用时，可以从L3里读取环境约束来实例化参数，比如一个依赖安装技能，会根据L3认知里的操作系统（Alpine/Debian/macOS）自动选择合适的包管理器命令，而不是写死一个。

三层从下到上是**证据→模式→知识**的抽象链。每层都保留对自己下层证据的链接，可追溯、可审计、可修正。这个分层本身的价值在于：当后续经验与某条L2策略冲突时，你能顺着证据链接定位到底是什么变了，是环境约束错了，还是触发条件过时了，还是那几条原始轨迹本身就不可靠。

# 技能从哪来：一道两步的晋升闸门

有了L2策略，不等于就有了技能。L2是内部抽象，可能不完整、可能不稳定、可能不该被Agent直接调用。技能是部署对象。MSCE在两者之间设了一道两步的晋升闸门。

**第一步：证据和收益。** 源L2策略必须还有支撑证据（不是已经被新经验推翻的过时策略），且效用增益必须为正。增益怎么算？MSCE用了一种启发式估计，把关联了该策略的轨迹的值函数均值，跟同一评估池里其余轨迹的均值做差。差值为正，说明用了这个策略的轨迹整体质量更高。不是因果推断，是启发信号，够用来决定"值不值得提成技能"。

**第二步：稳定性。** 近期证据跟当前的触发条件、执行流程、边界范围一致，不用大幅重写。如果策略本身还在剧烈震荡（每次新轨迹进来都在改写触发条件和流程），说明这模式还没收敛，提成技能只会引入噪音。

两步都过了，MSCE开始结晶化。结晶不是简单把L2字段复制一遍，它用正例证据归纳出共同流程，用反例证据收缩适用范围并生成反模式（anti-pattern），加一个白名单工具集（只允许证据里实际出现过的工具）。一份结构化的技能卡片出炉：触发条件、执行流程、验证规则、适用范围、证据锚点、决策指引、可靠性评分。

每个草稿技能过一道确定性验证器：Schema完整吗、证据引用来自支撑集吗、声明的工具在白名单里吗、有没有发明未支撑的命令。验证失败直接丢弃，不对外暴露。

部署后，技能带追踪可靠性。MSCE用平滑成功率估算，成功次数加一除以总调用次数加二，防止样本少的时候虚高。可靠性高的进活跃检索，低的挂着观察或归档。用户纠正或拒绝会降低可靠性并可能收缩适用范围。

# 反馈怎么传到该传的地方

一个二十步的任务最后拿到一个终局信号，0或1。你怎么把这一个信号分摊到每一步上？

MSCE的做法叫**反射加权价值回填**。Agent在大多数交互步上都有自我反思，"这步选择了旋转工具，方向判断正确，后续裁切应该能用"。这些反思有的靠谱，有的是空话。MSCE用一个提示打分器评估每条反思的质量：是否忠实于实际行为、是否具体、是否因果相关、是否可迁移。靠谱的反思获得高权重α，空话或套话获得低权重。

终局奖励从最后一步开始往回传播。每一步的价值等于：α乘以终局奖励，加上(1-α)乘以后续步骤的已回填价值再打折。α高的步骤，那些反思确实捕获了关键决策信号，直接吸收了更多终局反馈，α低的步骤大部分价值从后往前继承。

效果很直观。一个"发现图片方向歪了，需要旋转"的步骤，反思写得具体、因果链清晰，α就高。这条步骤就变成记忆中的高价值证据。一个"OK，继续下一步"的空洞反思，α几乎为零，它的价值纯靠后面步骤带。稀疏的终局信号，通过密集但质量参差的自我反思，被重分布成了可区分步级价值的信号。记忆构建和技能结晶不再瞎猜哪步关键。

# 在五个领域上长出来的技能

实验在EvoAgentBench上跑，覆盖信息检索、数学推理、软件工程、代码实现、知识工作五个领域。GPT-5.2做Agent骨架，GPT-4o做辅助裁判。所有方法用同样的工具访问权限、同样的交互预算、同样的任务顺序。记忆和技能只在在线进化episode中累积，不更新模型权重。

MSCE在五个领域全部拿到最优或并列最优。信息检索+4.61pp，数学+4.00pp，软件工程+15.39pp，知识工作+5.17pp，均相对于每领域最强非MSCE基线。代码实现领域，MSCE跟EvoSkill并列61.54% Pass@1，成本从3.9步压到2.0步。增益不是靠多花推理预算堆出来的。

消融实验拆开来：去掉三层层次结构压平记忆（FlatMemory），信息检索从26.15%掉到10.77%。去掉技能结晶化（只有L2策略，不提成可调用技能），五个领域全面下降。去掉反射加权（统一对待所有反思，不用α），数学从47%掉到40%。L3环境认知、价值校准、每一步都有各自的贡献。

跨域迁移也挺有意思。在源领域上进化好的记忆和技能，迁移到目标领域继续进化，六组迁移对全部正向提分，平均+3.93pp。学到的不是领域特异的死模板，是可迁移的解题结构。

长程进化实验下，Pass@1随经验累积单调递增，从p0到p100，数学+17pp、软件工程+15.39pp、信息检索+13.84pp。归一化成本先涨后降，到p100低于p0水平：Agent用着用着，不光更准了，也更省了。

# 记忆治理跟Skill治理的接口

MSCE做的事，跟Agent-insight的Skill全生命周期治理在同一条延长线上。Agent-insight管的是Skill从评测、准入、部署到进化的治理闭环。MSCE补的是源头治理：技能不应该从噪音轨迹里直接蒸馏，而应该从一层层被验证、被证据锚定、被价值信号校准的记忆结构中生长出来。

MSCE的三层记忆架构给出了一个可操作的答案：L1提供可审计证据，L2提供可修正的策略抽象，L3提供可复用的环境知识。三道闸门，证据支撑、正增益、稳定性，一起决定"什么能变成技能"。可靠性追踪和适用范围收缩负责"技能什么时候该退场"。这不是一次性的蒸馏，是一种技能从记忆中持续生长、持续修正、持续退役的治理过程。

把Agent-insight的四维评测门禁接在这个记忆-技能进化管道上：MSCE在运行中自动产生候选技能并附带证据链和可靠性估算，Agent-insight做上线前的最终验收。技能就不再是两种来源，人写的或用一条轨迹蒸馏的，而是从一个被治理的经验基座上自己长出来的。
