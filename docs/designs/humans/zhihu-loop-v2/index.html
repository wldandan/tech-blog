1自动 SCOUT

hermes cron 在周一/周四 09:00 无声启动 run-cycle.sh，调用 opencli 扫热榜和 8 个大词，推飞书候选卡片。

关键：完全自动，用户不需要手动触发，早上打开飞书就能看到候选。

2门 1：选题确认

agent 不能自行决定回答哪道题——这是用户的判断。在飞书回复「答 <qid>」后，agent 自动检索 tech-blog 素材。

强制确认门，不可绕过。

3WRITE（Claude Code）

由 Claude Sonnet 4.6 起草答案，引用至少 1 篇 tech-blog 旧文，加「延伸阅读」，经 humanizer-cn 去 AI 味。

关键：WRITE 不在 hermes 里跑，始终是 Claude Code 保证质量。

4门 2 + 发布

草稿通过后推飞书，用户确认「发」→ publish.sh 归档 git →用户网页粘贴发布 → fill-back-url.sh 记录 URL。

知乎无公开发布 API，网页发布是合规红线，不可绕过。

5自动 MEASURE + 快报

每天 08:00 hermes 回收所有已发布回答的 votes/rank，生成进度快报推飞书/微信，包含 goal 进度条和建议。

目前快报是回答赞聚合，账号粉丝数待 opencli 升级后加入。

目标

3 个月 1W 粉：指标分解

杠杆在高赞回答——2 篇 ≥500 赞可带来约 4000 粉，10 篇 ≥100 赞再带 3000 粉，长尾补齐剩余。

粉丝增量 10,000 0 爆款带动
回答数 30 3 约 3 天一篇
高赞 ≥100 10 0 精选竞争小的题
爆款 ≥500 2 0 打热榜高热度
总获赞 5,000 0 累计指标

SCOUT 优先策略：热度 ≥100 + 回答数 ≤50 + 标题含"为什么/本质/怎么/如何"钩子词 + 命中用户专长（AI Agent / Harness / Claude）。

决策

关键选择与原因

WRITE 由 Claude Code 执行，不由 hermes LLM
用户明确选择。hermes 配置的 LLM 未知、质量不可控；答案质量直接影响赞数和涨粉速度，必须用 Sonnet 4.6。
hermes cron 用 --no-agent 模式
SCOUT/MEASURE/daily-report 是纯 bash 逻辑，不需要 LLM。用 --no-agent 零 token 消耗，执行更快，不依赖 LLM 配额。
每日快报用回答赞聚合代替账号粉丝数
实地检查发现 opencli zhihu 无 profile/stats 命令，无法自动读账号粉丝数。回答赞是现有能力，且与涨粉强相关，先跑起来。
发起问题用"门 3 + 用户网页操作"而非自动化
opencli 无 create-question 命令；playwright 有账号安全风险且维护成本高。agent 起草草稿、用户一键发起，合规且稳定。
topic-scout 内嵌在 run-daily.sh 周一触发
避免再注册一个 hermes cron job，周一已是最低用量日，顺带触发不增加心理负担。
